## Algorithme de convertion postfixe -> infixe

- Si l'élément lu est un opérande, le push dans la pile.
- Sinon, c'est un opérateur:
  - On dépile deux éléments `e2` et `e1`
  - On empile la forme infixe: `"(" + e1 + " " + opérateur + " " + e2 + ")"`
- La pile contient à la fin l'expression infixe complète: on a juste a le pop.

**Exemple**: 3 2 + 7 2 2 + - \*

- (Pile vide)
- 3
- 3 2
- (3 + 2)
- (3 + 2) 7
- (3 + 2) 7 2
- (3 + 2) 7 2 2
- (3 + 2) 7 (2 + 2)
- (3 + 2) (7 - (2 + 2))
- ((3 + 2) \* (7 - (2 + 2)))

En java:

```java
public class Infixe {

    // Convertis de Postfixe à Infixe
    public static String convertirInfixe(String[] expr) {
        Stack<String> pile = new Stack<>();
        for (String s: expr) {
            if (s.equals("+") || s.equals("-") || s.equals("*") || s.equals("/")) {
                String operande2 = pile.pop();
                String operande1 = pile.pop();
                String nouvelleExpr = "(" + operande1 + " " + s + " " + operande2 + ")";
                pile.push(nouvelleExpr);
            } else {
                pile.push(s);
            }
        }
        return pile.pop();
    }
    public static void main(String[] args) {
        String exprPostfixe = "3 2 + 7 2 2 + - *";
        String[] exprDecoupe = exprPostfixe.split(" ");
        String exprInfixe = convertirInfixe(exprDecoupe);
        System.out.println(exprInfixe);
    }
}
```

## Algorithme de convertion postfixe -> infixe

On suppose qu'on utilise des parenthèses partout (pas de priorité)

- On init un `String result = ""` et une `Stack<String> pile = new Stack<>()`, et on parcourt l'expression de gauche à droite
- Si c'est:
  - Un opérande: on l'ajoute à `result`
  - Un opérateur, on l'empile
  - Une `(`: on fait rien
  - Une `)`: on dépile un opérateur et on l'ajoute à `result`
  - Un opérateur: on le push dans la pile
  - A la fin, la variable `result` contient l'expression postfixe

# Appels de fonction

- Quand on appelle une fonction, on fait un saut vers la première ligne du code de cette fonction.
- Mais à la fin, on doit revenir à l'endroit où on était avant l'appel.

Pour cela, on utilise une **pile d'appels** (call stack) pour mémoriser le numéro de ligne courant de chaque fonction

Voir exemple sur la slide

## Variables locales
Chaque fonction a ses propres variables locales, qui sont stockées dans la pile d'appels. Chacune est stockée dans la case mémoire correspondant à sa fonction
Deux variables avec le même nom dans deux fonctions différentes sont indépendantes.

On peut utiliser le debugger (de VSCode par exemple) pour voir la pile d'appel et les variables locales.
